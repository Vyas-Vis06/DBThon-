# Policy seed staging notes

`rule_parameter_seed.csv` is a human-readable staging file, not a direct SQL `COPY` of `rule_parameter`. The staging-only columns `profile_code`, `parameter_code`, `source_key`, `gear_code`, `gate`, `comparison`, `applicability`, and `notes` require loader handling. Map `profile_code` to the intended `rule` row and `parameter_code` to `rule_parameter.param_key`; resolve `source_key` to `legal_clause.id` and each nonblank symbolic `gear_code` to `gear_item.id`. Fail the load if any mapping is missing or ambiguous. Do not embed generated UUIDs in this portable seed.

`comparison` records the operator for review, but runtime SQL must dispatch fixed comparisons by the approved `param_key` allowlist. Never interpolate this CSV field into SQL or execute it as an arbitrary operator. `scope` and `source_category` use the schema’s controlled vocabularies. Blank numeric/text/gear fields are intentional according to `kind`.

Every parameter row belongs to `EDU_LAB_V1`, a controlled educational profile. It is not an active deployment policy and does not create a real `ALLOW` rule. Oxygen, crew, work/rest, equipment inspection interval and training interval rows are source-text references with current applicability pending. Gear and readiness selections are operational demo choices even where their catalogue or subject matter has an official source reference. Gear codes in this file are symbolic; loader resolution must check the catalogue first.

The 900-second freshness, 120-second future-clock tolerance, H2S `<10 ppm`, LEL `<10%`, CO `<25 ppm`, and 00:00–24:00 window are operational demo settings. The strict gas comparison operators are explicit educational assumptions; CO is not asserted as a statutory threshold. The full-day time profile does not implement the source daylight clause (Rule 6(3)(k)(i)); daylight remains a separately documented reference/controlled explanation. Six-month inspection is a calendar-month interval, not a fixed-day duration.
